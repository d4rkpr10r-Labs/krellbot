# M35: research depth: drill-down, robustness, regime comparison and drift review

**Status:** proposed; agents start M35 only after the owner merges it and
after earlier milestone files' agent tasks, unless the owner reorders.

**Depends on:** M29 (P05: M29.1, F22 run record; M29.2, F26 coverage
manifest; M29.3, F30 trade list and risk metrics, which creates
`docs/metrics.md`; P11: M29.5, F21 batches; M29.6, F23 holdout lock; M29.9,
F24 cost scenarios; M29.7, F20 labels). M28 (M28.8, F03 fills side-car;
M28.2, F06 stop and pause semantics). M30 (M30.1 paper ledger). M31 (M31.8
and M31.9 backtest-to-paper comparison).

**Exit / gate:** a user can zoom a research chart, open any bar from a
marker, see fill-accurate markers and a timed equity line, review the
drawdown spread from reordering a backtest's own trades, compare a
regime-filtered revision with its baseline on one pinned window, and record
a keep, pause or retire decision per paper deployment beside expected versus
observed results. Every one of these says what it is not: no forecast, no
significance test, no market performance.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
`PAPER_ONLY_RELEASE` stays True. Outputs go in side-cars keyed by run id,
outside `research-jobs/` (never `*.json` there); the 13-key receipt, research
detail keys, the stored `{legacy_receipt, trace}` result and JobV1 stay
pinned. No new chart dependency. Nothing switches a strategy automatically.
UI follows `docs/design-system.md` (`KRELL-SIGNAL-20261010`).

**Decisions adopted from the approved roadmap:**

- A specialist research-method review gates the trade-order resampling
  (M35.8 before M35.3 merges).
- Base-asset accumulation demand rests on one 2017 source; the owner
  validates it (M35.9) before M35.7 starts.
- F53's first slice is a research-only paired comparison. Regime-based
  scale-down sizing in the tick is a later risk-path change, not booked here.
- The holdout is never used for selection (M29.6's lock applies to every
  comparison here).

**Parallelism:** M35.1 ∥ M35.4 ∥ M35.6 first. M35.2 after M35.1. M35.3 after
M35.8 for merge. M35.5 after M35.4. M35.7 after M35.9.

## Epic M35-A — Drill-down

- [ ] **M35.1 Zoom the research chart and open bars from markers.** In
  PriceWithTradesChart and ResearchView add a keyboard-accessible start and
  end bar range control that zooms the price and trade chart over the trace.
  Clicking or pressing Enter on a marker calls `onSelectBar`, so the trace
  list scrolls and the bar detail opens. Echo the range in the provenance
  strip and relabel markers 'signal', not fill. No backend change.
  - Scope: `frontend/src/features/research/PriceWithTradesChart.tsx`, `frontend/src/features/research/ResearchView.tsx`
  - Deps: none
  - Accept: `cd frontend && npm run test:unit -- --run src/features/research/PriceWithTradesChart.zoomSelectsBar.test.tsx`

- [ ] **M35.2 Fill-accurate markers and a timed equity line.** Draw fill
  markers, stop exits included, from M28.8's F03 fills side-car, kept apart from
  signal markers. Add a per-bar timed equity side-car keyed by run id so the
  equity chart zooms with the M35.1 range; the 64-point receipt curve stays as
  it is. Missing data shows 'unavailable', never a drawn guess.
  - Scope: `src/krellbot/application/research.py`, `src/krellbot/api/jobs.py`, `src/krellbot/api/app.py`, `frontend/src/features/research/EquityCurveChart.tsx`, `frontend/src/features/research/PriceWithTradesChart.tsx`
  - Deps: M35.1; M28.8 (F03 fills side-car); M29.1 (F22 run record)
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_timed_equity_sidecar.py && (cd frontend && npm run test:unit -- --run src/features/research/EquityCurveChart.zoom.test.tsx)`

## Epic M35-B — Robustness

- [ ] **M35.3 Drawdown spread from reordering a backtest's own trades.** New
  `backtest/robustness.py` resamples the order of the realized round-trip
  returns from M29.3's trade list with a fixed, documented seed and a bounded
  number of paths, and reports the distribution of max drawdown. Label:
  'reordering of this backtest's own trades, not a forecast or significance
  test'. Side-car plus a ResearchView table; method, independence assumption
  and limits in `docs/metrics.md`. Merges only after M35.8.
  - Scope: `src/krellbot/backtest/robustness.py` (new), `src/krellbot/application/research.py`, `src/krellbot/api/app.py`, `frontend/src/features/research/ResearchView.tsx`, `docs/metrics.md` (created by M29.3)
  - Deps: M29.3 (F30 trade list, `docs/metrics.md`), M29.1 (F22 run record); M35.8 for merge
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_backtest_trade_order_resampling.py`

## Epic M35-C — Drift review

- [ ] **M35.4 Strategy review decision log.** New
  `application/strategy_review.py`: a home JSON store keyed by armed (venue,
  pair, canonical pack sha recomputed from the armed pack file) that records
  the linked research run id and operator decisions (keep, pause entries,
  retire) with reason and timestamp. Read and write routes; writes keep the
  session, CSRF and origin checks. Pause and retire only record the decision
  and point to the existing PaperService commands. No `run/` edits.
  - Scope: `src/krellbot/application/strategy_review.py` (new), `src/krellbot/api/app.py`
  - Deps: M31.8; M29.1 (F22 run record)
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_strategy_review_decision_log.py`

- [ ] **M35.5 Expected versus observed review card.** Under the paper
  Status view's Advanced section, show the linked run's summary and window
  (expected) beside the M31.8 counts since arm (observed), with 'no
  statistical test applied', the decision history and buttons that record a
  decision. Paper evidence and backtest stay labelled apart.
  - Scope: `frontend/src/features/paper/StrategyReviewCard.tsx` (new), `frontend/src/features/paper/StatusPanel.tsx`, `frontend/src/features/paper/client.ts`
  - Deps: M35.4, M31.9
  - Accept: `cd frontend && npm run test:unit -- --run src/features/paper/StrategyReviewCard.test.tsx`

## Epic M35-D — Regime comparison and base-unit benchmark

- [ ] **M35.6 Paired backtest of a regime filter against its baseline.** A
  paired research request runs two saved revisions (for example a
  regime-filtered pack and its unfiltered baseline) on one pinned window and
  one fee and slippage setting, and refuses with a typed code when windows or
  data differ. A side-car stores both run ids; the Research view shows both
  receipts labelled backtest, each with its buy-and-hold block. M29.6's
  holdout lock and M29.9's cost scenarios apply.
  - Scope: `src/krellbot/application/research.py`, `src/krellbot/api/jobs.py`, `src/krellbot/api/app.py`, `frontend/src/features/research/ResearchView.tsx`
  - Deps: M29.6 (F23 holdout lock), M29.9 (F24 cost scenarios), M29.5 (job-kind validation)
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_paired_revision_comparison.py`

- [ ] **M35.7 Base-unit benchmark.** A pure helper in `backtest/metrics.py`
  computes base units per bar (equity / close) and final base units against
  the buy-and-hold quantity. Serve it from a side-car keyed by run id, not the
  stored result or research detail, and show 'Ending value in <base>
  (backtest)' under Research Advanced.
  - Scope: `src/krellbot/backtest/metrics.py`, `src/krellbot/application/research.py`, `src/krellbot/api/app.py`, `frontend/src/features/research/ResearchView.tsx`
  - Deps: M35.9; M29.1 (F22 run record), M29.3 (metrics in `backtest/metrics.py`, `docs/metrics.md`)
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_base_unit_benchmark.py`
