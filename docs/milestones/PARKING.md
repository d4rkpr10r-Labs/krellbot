- `run.tick(home=X)` appends the journal under `$KRELLBOT_HOME` but reads ownership from `X/journal`; harmless while both are the same directory.
- Paper taker-fee tables exist in four copies (`venues/paper._fee_bps_for` and `run._fee_bps_for_venue`, both on risk paths, plus `application/paper._PAPER_TAKER_BPS` and `application/research._default_fee`). They agree on every listed venue but fall back differently for an unlisted one: `run` gives 0, `venues/paper` 120 (Coinbase's), `_PAPER_TAKER_BPS.get(venue, 40)` 40, and `_default_fee` 120 for any venue but Kraken.
- `frontend/e2e/journey-harness/harness-negative-controls.spec.ts` "Python IPv6 and DNS refusals precede OS calls" fails on hosts without IPv6: `socket.socket(AF_INET6)` raises `EAFNOSUPPORT` before the guarded `connect` runs, so the control proves nothing there.
- `run.tick` journals nothing when a pair's latest candle was already journaled (`_already_journaled`), so a feed that keeps returning one old candle leaves no stale read: `feed_stale` only sees a new candle that is already old, and a stuck pair shows only as health `stale_check` or venue `scheduler_stale`.
- `npm run test:journeys` writes its HTML report to `frontend/playwright-journey-report/` (playwright.journeys.config.ts:26), which `.gitignore` does not list, so every local journeys run leaves an untracked folder.
- The backtest never raises the stop: `backtest/engine.Backtester.run` sets `stop_price` only on an entry from flat, while `run.tick` calls `raise_stop` on a later long bar whose stop is higher. So `explainPack.ts` `STOP_RAISE_SENTENCE` ("only raised, never lowered") holds for paper and live but not for research backtests, and the same pack can stop out at different prices in the two.
- `frontend/src/features/referral/ReferralDisclosurePanel.tsx` says "Exchange credentials never leave the OS keychain" and Settings → Privacy says exchange keys are "never transmitted": keys are sent to the exchange, and a `KRELLBOT_<VEN>_KEY`/`_SECRET` override or `_KEYFILE` bypasses the keychain (`secrets.get`).
- `PortfolioHistoryPanel` and `PaperPnlPositionChart` draw axis labels at a fixed 10px inside a fixed-width SVG `viewBox` scaled to the panel, so at 390px they render at roughly 3–5px; legible phone charts need width-aware chart sizing in the TSX, which CSS alone cannot do.
- `npx tsc -p frontend/e2e/tsconfig.json` reports 3 errors in `e2e/ns20-100k-rows.spec.ts:180` and `e2e/workspace-setup-tour.spec.ts:11,53`; `npm run typecheck` does not cover `e2e/`, so nothing catches type errors in specs.
- Operations Alerts search's accessible name stays "Search alerts by code, venue, or kind" (pinned verbatim by `frontend/src/features/operations/AlertsFilter.aria.test.tsx`) although M28.16 made it match pair too; only the placeholder says pair.
- J5.4 failed once in a local full journeys run on 272fc1f before its `test.fail` line: `armPaper` → `openTechnicalJson` (`frontend/journeys/helpers/journey-steps.ts:278`) waited 20 s for the raw JSON textarea, which stayed hidden; it passed as an expected failure in the next two full runs.
- Paper slippage exists in two copies: `application/paper._PAPER_SLIPPAGE_BPS` (5) copies `venues/paper.SLIPPAGE_BPS` so `GET /api/v1/paper/assumptions` never imports the venue risk path. `tests/test_paper_assumptions_route.py` pins them equal, so changing one fails CI until the other changes too.
- `venues/coinbase._ref_from_coinbase` takes `filled_size or qty`, so a listed Coinbase order with `filled_size` "0" or missing comes back from `place_entry_with_stop`'s already-listed path with the requested `base_size` as `filled_qty`, and a fresh dispatch of that coid credits it in full (Kraken's equivalent was fixed in M28.3).
- `tests/test_ns12_operational_store.py::test_second_writer_is_refused_while_the_lock_is_held` failed once on Windows 3.13 CI at `assert started.wait(timeout=2)` (PR #659, run 45862473531), then passed on the next run with the same code; the 2 s thread-start wait looks too tight for Windows runners.
- `krellbot service install` (the documented always-on entry in `docs/service.md`) writes only the tick unit; only the workstation's scheduler install adds M28.20's heartbeat units, so a host scheduled from the CLI gets no heartbeat check.
- `venues/kraken.build_entry_with_stop_form` and `place_exit` send both `cl_ord_id` and `userref` on AddOrder, but Kraken's AddOrder reference (https://docs.kraken.com/api-reference/trading/add-order) says the two are mutually exclusive, so a real Kraken may reject every live order.
- Kraken `raise_stop` uses EditOrder, which replaces the stop with a new txid and documents no link back to the entry (userref is explicitly not retained), so since M28.24 a raised Kraken stop's fill is unlinkable and holds that arm's exits until an operator resolve; recording EditOrder's returned `txid` against the entry coid, or using AmendOrder (which keeps ids), would make it linkable.
- Kraken `TradesHistory` names a trade's pair by its asset-pair key (e.g. `XXBTZUSD`) while arms use the requested name (`XBTUSD`), and `KrakenVenue.rules` reads `AssetPairs` by the requested name; stop-fill attribution compares `Fill.pair` to the armed pair, so it only works where the key equals the name (e.g. `SUIUSD`).
- A repaired live stop whose reply was lost and that fills before the next tick is settled `filled` by `_resolve_obligations`, which journals its `stop_qty` with no `stop_fill_ids` (Kraken and Coinbase outcomes carry none); the same tick's `_stop_fills_for` then credits its linked fills again. The double decrease is clamped at 0, so nothing external is sold, but the journal carries the stop quantity twice.
- Live buy fills cannot be linked to their entry coid: Kraken `TradesHistory` trades name `ordertxid`, Coinbase List Fills rows carry no `client_order_id`, and both adapters' `_link_sell_fills` look up sells only. So M28.31's `run/daily_loss` cannot price a live entry and, by the owner's fail-closed decision, a live arm's equity is uncomputable once it holds a live buy: with a limit it holds entries with `loss_limit_unavailable`. Linking buy fills as sells are linked would let live arms compute equity.
- `run.tick` reloads and saves `config.json` after its pack loop without `config._paper_command_transaction`, so a pause, resume, raise-stop or `risk.set_daily_loss_limit` command saved between that reload and save is overwritten by the tick.
- Re-selecting Run re-reads only the paper status panel's status and owned position; `PaperPnlPositionChart` re-reads only on a confirmed arm (`refreshKey={armEpoch}` in `StatusPanel.tsx`), so after a scheduler or CLI tick the Run chart can lag the "Owned position" line until the panel remounts.
- `supervise.last_tick_ts` (and so `scheduler_stale` and doctor's `last_tick_age_s`) takes the latest `kind=tick` journal record of a venue, so a record written outside the scheduler (an operator close, an operator resolve, `reconcile_intents`) at time now makes a stopped scheduler look alive until the stale threshold passes again.
- Live `cancel_stops` (kraken.py:571, coinbase.py:551) cancels every stop resting on the pair, including stops the user placed by hand, and Coinbase's ignores the Cancel Orders reply; the tick's exit path then sells without checking that the stop is gone (M28.32's close re-reads the account and refuses instead).
- `StrategyDraftService` never checks the shape of a `revision_id` (or of a pack `id`, which becomes `drafts/<id>/` before any lint) before joining it into a path: `exists("../../outside")` is true when `<home>/outside.json` exists. The agent boundary now validates both (`krellbot.agent.core.path_id_refusal`: 64 lowercase hex, pack schema id pattern) for MCP and Krell; the remaining gap is the draft store's own non-agent callers (the web routes only type-check `revision_id`), so the store itself could check ids before any path join.
- The agent `paper_arm` reaches `run.arm_pack` (via `PaperService.arm`), which `print`s "armed ..." / refusal text to stdout; under the stdio MCP server (M38.9) stdout carries protocol frames only, so that server must redirect or silence stdout around tool calls.
