# M39: Krell's first session

**Status:** proposed. Agents start M39 only after the owner merges this
file. Once it merges, agents take M39 before the unchecked agent tasks in
M29–M37 (owner decision 1).

**Source:** the owner's first local session with Krell on 2026-11-28 (the
Windows candidate built from `be24f76`, with a custom OpenAI-compatible
endpoint). Every task traces to something in that session that broke,
confused, or felt unfinished.

**Depends on:** M38 agent tasks (all merged). M38.25 and M38.26 stay with
the owner.

**Exit / gate:** A new user opens Krellbot and reads a welcome that names
three ways in: Krell, the tour, or Skip. Connecting a model is a guided
flow: provider and key on one screen, then a model chosen from the
provider's own list with plain pros and cons. Krell sounds like someone
worth talking to. On paper she follows the person's choices within their
limits. She drafts, validates, loads data and backtests in one turn without
guessing formats or stopping mid-task. Her activity reads as plain words.
Token numbers live in Settings → Usage and match the provider. Run has a
Guided mode a beginner can follow. The home screen and Settings read as one
flat, modern surface, and presses and tab changes move the way krellbot.dev
does.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
`PAPER_ONLY_RELEASE` stays True. Agents never choose orders, override risk,
arm live, read keys, close positions or change live strategies. The
loopback API keeps its authentication, session, CSRF, origin and host
checks, and every new route uses `_gate_get` or `_gate_state_change`. Tests
use fake AI transports, fake market-data transports, the fake keyring and an
isolated home; CI makes no real provider or exchange calls. Nothing about
agents, conversations or usage goes to `krellbot.dev`. The UI draws the
Simulated and Not financial advice labels from tool results, never from
model text. Never present backtest or fixture results as market
performance.

## Owner decisions (adopted when this file merges)

1. **Order.** M39 goes before the unchecked agent tasks in M29–M37.
2. **Krell's voice.** Friendly, edgy, tech-focused and exciting: someone
   who makes people want to try things. She keeps the mode emoji (the
   turtle for standard). On paper she follows the person's choices within
   the operator's limits. She gives at most one short note per setting and
   never repeats warnings. In the workstation she says "not financial
   advice" once per conversation, when she first suggests something; result
   cards carry the label from then on. In MCP clients the M38 rule stands
   (she says it herself each time). All other honesty rules are unchanged.
3. **Limits are the person's.** The operator policy is the person's own
   settings. Krell names Settings → Agents & limits when a limit matters.
   She never calls a limit "your operator's rule" as if someone else set it.
4. **Positioning copy.** "Your AI is Krell's brain. It's optional, but it
   unlocks Krell and Krellbot's AI features."
5. **Brain tiers** (initial; the M38.25 real-model evals may move a
   provider). The criteria shown to users are dependable multi-step tool
   use, following strict formats, and long context. No benchmark numbers or
   performance claims.
   - **Best brains for Krell:** Anthropic; OpenAI (API key or ChatGPT
     sign-in); Google Gemini; xAI.
   - **Good:** DeepSeek; Mistral; GLM 5.3 (Z.ai); Kimi K3 Pro (Moonshot
     AI).
   - **Depends on the model you pick:** OpenRouter, custom endpoints.

   Owner amendment (2026-11-28): xAI moves to Best, and GLM 5.3 and Kimi
   K3 Pro join Good. Z.ai and Moonshot AI become API-key providers (M39.10).
6. **Usage.** The chat shows only a small context ring. Token counts live
   in Settings → Usage and use provider-reported usage only. A call the
   provider did not report shows as "not reported", never as zero.
7. **Turn budget.** A turn allows up to 24 tool calls (was 8). A call whose
   tool and arguments match one already refused in the same turn is not
   sent again. When the budget runs out, Krell writes her own summary of
   where things stand, and a "Keep going" reply continues.
8. **Design.** Amend `docs/design-system.md`. Any section has at most two
   surface levels: the page and one panel. The page gradient runs the full
   viewport behind content. Presses, tab changes and view changes animate
   to match krellbot.dev, and stay off under `prefers-reduced-motion`. The
   contract id stays `KRELL-SIGNAL-20261010`.
9. **Run modes.** Run has Guided (the default for new users and the
   standard profile) and Advanced (today's screen, unchanged). The choice
   is remembered.

**Parallelism:** M39.1 → M39.2 (both edit `agent/core.py`). M39.3 → M39.7 →
M39.8 (all edit `krell_loop.py` and `KrellConversation.tsx`). M39.9 ∥
M39.10, then M39.11. M39.4, M39.5 and M39.6 can run beside any of those.
M39.12 → M39.13. M39.14 → M39.15 (shared styles). M39.16 can run beside
anything outside `frontend/src/styles/`.

## Epic M39-A — Krell finishes what she starts

- [ ] **M39.1 The draft tool carries the pack format.** In the session,
  three drafts were refused with "pack must have a non-empty id". Krell
  then needed three more draft-and-validate rounds on one strategy to
  guess the pack shape from validator errors, and two turns in a row hit
  the tool-call cap. Build the `draft` tool's
  `pack` input schema from `src/krellbot/pack/schema.json`, and put one
  complete runnable pack in its description. When `id` is missing,
  generate one from the label, unique among drafts. `draft` runs the
  validator and returns `runnable` and any errors in the same result, so
  one call saves and checks. MCP clients get the same tool.
  - Scope: `src/krellbot/agent/core.py`, `src/krellbot/application/strategy.py`, `tests/test_krell_draft_tool_format.py` (new)
  - Deps: none
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_krell_draft_tool_format.py`

- [ ] **M39.2 Krell can load public price data.** On a fresh home the
  candle cache is empty. Krell called `market_snapshot` four times and got
  `market_snapshot_not_found` each time, and nothing could be backtested.
  Add a `load_candles` tool (research effect, heavy cost, so the
  workstation asks first). It fetches public candles for a venue, pair,
  timeframe and window through the existing public fetchers in
  `src/krellbot/data/`, writes them to the local cache, and reports what
  loaded. It uses no keys. Refusals for missing data from
  `market_snapshot` and `backtest` name `load_candles` as the next step.
  - Scope: `src/krellbot/agent/core.py`, `src/krellbot/agent/tools_research.py`, `src/krellbot/agent/tools_read.py`, `tests/test_krell_load_candles.py` (new)

  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_krell_load_candles.py`
