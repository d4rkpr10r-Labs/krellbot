# M34: agent and programmatic access

**Status:** proposed; agents start M34 only after the owner merges it and
after earlier milestone files' agent tasks, unless the owner reorders.

**Depends on:** M28 (P01: M28.3 and M28.22–M28.27, F04 live order truth;
P03: M28.8, F03 decision receipts, and M28.12, F14 explanations, which agent
drafts are reviewed against). M29 (M29.1, F22 run record and receipt digest;
M29.2, F26 coverage manifest; M29.5, job-kind validation; M29.4, job
progress). M32 (M32.2 venue capability matrix, which the discovery document
reuses).

**Exit / gate:** a programmatic client can discover venues, research venues,
job kinds, limits and MCP tools from one document; can preflight a research
job against a declared bar cap; and can export a reproducibility bundle for
any finished run. MCP backtests carry the same run id and receipt digest as
web jobs. A local stdio MCP server exposes only the existing allowlist, and
drafts made by an agent are marked for review in the Strategies list. No
model is called and nothing live is reachable.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
`PAPER_ONLY_RELEASE` stays True. AI and agents never choose orders, override
risk, arm live or read keys. The loopback API keeps its authentication,
session, CSRF, origin and host checks; no task adds a token or another auth
path. JobV1, `GET /api/v1/capabilities` and the stored research result stay
pinned. The CLI stays plumbing: the stdio server gets a launcher entry only.
Telemetry stays opt-in. Backtests are never presented as market performance.

**Decisions adopted from the approved roadmap:**

- Decision 16: a stdio MCP wrapper is approved only if job creation goes
  through the loopback API, never a second JobManager over the same home.
  No non-browser API auth until scopes are designed (M34.11), so M34's MCP
  server creates no jobs. The agent-origin badge (M34.5) ships before the
  owner decides whether agent drafts may paper-arm without review (M34.8).
- Decision 12: hosted AI, a hosted relay and remote compute stay deferred
  until M28 lands. Preflight estimates local work only.
- Job-kind validation is M29.5's (its batch kind is the first new kind, and
  M29.9's sweep reuses it); M34 does not repeat it. M34.4 registers the
  `export.reproducibility` handler that M29.5 refuses until it exists.

**Parallelism:** M34.1 ∥ M34.5 ∥ M34.7 first. M34.2 after M34.1. M34.3 after
M34.2. M34.4 after M34.2. M34.6 after M34.5, M34.8 and M34.9.

## Epic M34-A — Receipted research contract

  `POST /api/v1/research/jobs/preflight`, session and CSRF gated like submit,
  backed by an `application/research.py` helper that returns the bar count
  after windowing, indicator count, queue position and a declared bar cap
  without running the engine. Submit refuses runs above the cap with a typed

  the M32.2 venue matrix, research venues, job kinds, `MAX_RUNNING_JOBS` /
  `MAX_QUEUED_JOBS`, the M34.1 bar cap and `mcp.ALLOWED_TOOLS`. Lift
  `KEYS_VENUES` out of `create_app` into a module constant.
  `GET /api/v1/capabilities` stays unchanged
  (`test_m1r_fa_activation.py:346`). No new auth.
  - Scope: `src/krellbot/api/app.py`, `src/krellbot/application/venue_capabilities.py` (from M32.2)

## Owner decisions and gate

- [ ] **M34.8 [owner] Agent paper-arm default.** After M34.5 ships, decide
  whether drafts with origin 'mcp' may be paper-armed through MCP without a
  review in the workstation (today the default user policy allows it). If
  review is required, MCP `paper_arm` refuses agent drafts with a typed code
  and the user arms them from the web app.
- [ ] **M34.9 [owner] MCP SDK dependency.** Approve or refuse adding an MCP
  SDK dependency for M34.6.
- [ ] **M34.10 [owner] First BYOK AI provider.** Choose the first
  bring-your-own-key AI provider, or none yet. Nothing in M34 calls a model;
  AI explanation of receipts becomes a task only after this.
- [ ] **M34.11 [owner] Scopes for non-browser clients.** Design and approve
  API scopes before any token-based client or MCP job creation through the
  loopback API. Until then programmatic access stays browser-session and
  in-process MCP only.
- [ ] **M34.12 [owner] M34 gate.** From a clean home, read the discovery
  document, preflight and run a job, export its bundle, run the same
  backtest over stdio MCP and match its run id.

## Explicitly out of M34

- Hosted AI, a hosted relay, remote compute and any LLM call (decision 12,
  M34.10).
- API tokens, non-browser auth and MCP job creation through the loopback API
  (M34.11).
- Live arm, key reads or any live mutation over MCP or the API.
- Notebook plugins or arbitrary Python inside the engine.
- New CLI user features.
