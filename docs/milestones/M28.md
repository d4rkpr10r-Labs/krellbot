# M28: reproducible research and verifiable strategy evidence

**Status:** proposed. Agents do not start M28 until the owner merges this file.
M27 agent tasks stay ahead of M28 unless the owner reorders.

**Exit / gate:** every backtest, sweep and walk-forward result in the
workstation can be reproduced from a run id that names the pack bytes, dataset
manifest, engine version and parameters. Every sweep reports all of its
trials, including failures. A pack can carry an evidence record that the
engine verifies against the pack bytes and that keeps historical,
forward-paper and live results apart. Commercial entitlement lapse never
blocks exits, export or diagnostics. Alerts reach the operator without the
workstation open.

Everything in M28 is local and free. No hosted service, new egress, pricing
or tier ships here. Background, the capability matrix and later tranches are
in [platform-initiative.md](../platform-initiative.md).

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
Agents keep `PAPER_ONLY_RELEASE` True. Never present backtest, sweep or
fixture results as market performance.

**Parallelism:** M28.1 ∥ M28.3 ∥ M28.4 ∥ M28.10 first. M28.2 after M28.1.
M28.5 after M28.1 and M28.4. M28.6 after M28.3 and M28.5. M28.7 after
M28.1–M28.3. M28.8 after M28.7. M28.9 after the owner's lapse decision in
M28.11.

## Epic M28-A — Reproducible results

- [ ] **M28.1 Persist a run identity with every research result.** Store the
  `receipt_canonical_sha256` that `api/jobs.py` already computes (today
  `_extract_result` drops it) and add a `run_id`: sha256 over canonical
  `{pack_sha256, data_manifest_sha256, engine_version, fee_bps,
  slippage_bps, window, params}`. Reuse one canonical-JSON helper instead
  of adding another copy. Identical inputs give identical ids across runs
  and restarts; any input change changes the id.
  - Scope: `api/jobs.py`, `backtest/receipt.py`, research result API, Research view field
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_run_identity.py`

- [ ] **M28.2 Attach dataset manifests and pinned windows to research
  runs.** Wire `research/datasets.py` (`DatasetManifest`, coverage label)
  and `research/windows.py` (`pin_window`, `WindowChanged`) into
  `ResearchService`. The receipt records venue, pair, timeframe, first and
  last bar, bar count, gap count and dropped-row count. Report rows
  `data/cache.py::_parse_csv` drops instead of skipping them silently.
  A re-run whose pinned window resolves to different bytes refuses with a
  typed code.
  - Deps: M28.1
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_dataset_manifest.py`

- [ ] **M28.3 Risk-adjusted metrics with hand-computed reference
  fixtures.** Extend `backtest/metrics.py` with volatility, Sharpe and
  Sortino (per-bar returns, annualized by timeframe, risk-free 0), longest
  drawdown duration, profit factor, expectancy, win rate, total fees and fee
  impact (return with and without fees). Pin each against values computed by
  hand in the test. Add `docs/metrics.md` with each definition, assumption and
  limitation. Correct `docs/backtest.md`: a stop fills on the bar that
  triggers it. Strategy explanations keep their no-`win rate` rule.
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_backtest_risk_metrics_reference.py`

## Epic M28-B — Bounded research jobs

- [ ] **M28.4 Cooperative cancel and progress for research jobs.** The
  default runner checks `cancel_event` between bar chunks and stops within
  one chunk; `JobV1.progress` reports bars done / total. A cancelled job
  stores no partial result as success. Existing queue limits stay.
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_job_cancel_progress.py`

- [ ] **M28.5 Parameter sweep job with a complete trial ledger.** A new job
  kind runs a bounded grid over declared pack parameters (hard cap on trials,
  wall time and concurrency; refuse above the cap before starting). Persist
  every trial through `research/experiments.py` (`record_trial`,
  `DuplicateTrial`), including failed and cancelled ones. The result lists
  all trials and the total trial count beside the best one. The holdout
  window is never used for selection: the best trial is chosen on in-sample
  data and then scored once on holdout.
  - Deps: M28.1, M28.4
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_sweep_trial_ledger.py`

- [ ] **M28.6 Walk-forward evaluation.** Rolling in-sample / out-of-sample
  windows over the sweep. Report out-of-sample metrics per fold and in
  aggregate, the in-sample vs out-of-sample gap, and the parameter chosen per
  fold. Windows never overlap across a fold boundary (reuse
  `research/holdout.py`).
  - Deps: M28.3, M28.5
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_research_walk_forward.py`
