# M31: change deployments deliberately and explain paper versus backtest

**Status:** proposed; agents start M31 only after the owner merges it and
after earlier milestone files' agent tasks, unless the owner reorders.

**Depends on:** M28 (P01: M28.22, the F04 resolve action, before the apply
command in M31.6, and M28.2, F06's stop and pause semantics, for M31.14;
P02: M28.4, F07's venue data identity; P03: M28.12, F14's operator helper in
`explainPack.ts`). M29 (M29.1, F22 run record; M29.2, F26 coverage manifest;
M29.5, job-kind validation).

**Exit / gate:** before arming or re-arming, the user sees the path-level
diff against what is actually running and when each change takes effect,
can exclude assets account-wide and can carry a strategy (revisions plus
matching receipts) between homes. The web app can fetch public candle
history from hosts the tick already uses. For any paper arm with covering
data, the workstation classifies every bar since arm as a match or names why
paper differed from the backtest. Trigger semantics are documented and shown;
optional cooldown and maximum-hold fields have engine-and-tick parity tests.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
`PAPER_ONLY_RELEASE` stays True. Comparisons are labelled paper evidence and
backtest, never live results or market performance. Pinned shapes stay as
they are (the closed `/paper/armed` shape, the stored research result, JobV1,
condition sentences in `explainPack.ts`, the no 'win rate' rule); new outputs
go in new routes, side-cars or new elements. The CLI stays plumbing. UI
follows `docs/design-system.md` (`KRELL-SIGNAL-20261010`).

**Decisions adopted from the approved roadmap:**

- Decision 19: a web 'fetch public history' job is approved, limited to the
  public candle hosts the scheduled tick already contacts and disclosed in
  `docs/telemetry.md` (M31.7). It is a web job, not a CLI command. Licensed
  metadata (listing age, delisting history) stays deferred.
- Decision 15: additive pack-schema fields land one at a time, each in its
  own risk-path PR with engine-and-tick parity tests: `entry_cooldown_bars`
  first (M31.11), then `risk.max_hold_bars` (M31.13).
- Decision 18: PARKING line 18 stays, so applying a change remains a disarm
  and re-arm of the same (venue, pair) (M31.6).
- The read-only slices need no further owner decision. F70's demand is one
  source, so only a read-only cycle counter ships here.

**Parallelism:** M31.1 ∥ M31.5 ∥ M31.7 ∥ M31.8 ∥ M31.10 ∥ M31.12 ∥ M31.14
first (M31.8 uses M31.7's datasets when present; user CSVs work without
them). M31.2, M31.3 and M31.4 after M31.1. M31.6 after M31.2. M31.9 after
M31.8. M31.11 after M31.8 and M31.10. M31.13 after M31.11 and M31.12.

## Epic M31-A — Change deployments deliberately

- [ ] **M31.1 Show the diff before arming a different revision.** Export
  `diffRevisionPacks` from `RevisionCompare.tsx`. In the paper arm flow, when
  the selected revision differs from the bytes already armed on that
  venue/pair (read through the existing `paper.export` command), render the
  path-level diff and require an explicit confirm before disarm and arm.
  Read-only; no engine change; one pack per (venue, pair) unchanged.
  - Scope: `frontend/src/features/strategies/RevisionCompare.tsx`, `frontend/src/features/paper/StatusPanel.tsx`, `frontend/src/features/paper/ArmedRecordsList.tsx`
  - Deps: none
  - Accept: `cd frontend && npm run test:unit -- --run src/features/paper/ArmedRecordsList.diffBeforeArm.test.tsx`

- [ ] **M31.2 Compare a draft with the running revision.** A new GET
  (`_gate_get`, `StrategyDraftService`) returns an armed record's running
  revision_id, or null with 'not a saved revision'; `/paper/armed` is not
  widened. A RevisionCompare mode diffs the draft against it and says when
  each change takes effect: rules on the next closed bar after re-arm,
  `risk.stop` raise-only while a stop rests, `max_account_pct` on the next
  entry, markets or timeframe only after a disarm. Park the dead
  `pending_version` code and the sticky 'Deployed' label.
  - Scope: `src/krellbot/api/app.py`, `src/krellbot/application/strategy.py`, `frontend/src/features/strategies/RevisionCompare.tsx`, `frontend/src/features/strategies/libraryClient.ts`, `docs/milestones/PARKING.md`
  - Deps: M31.1
  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_running_revision_compare.py && (cd frontend && npm run test:unit -- --run src/features/strategies/RevisionCompare.running.test.tsx)`

- [ ] **M31.3 Saved arm defaults with pair overrides.** A small
  `application/arm_defaults.py` stores named paper-balance and venue defaults
  plus explicit pair overrides in `arm-defaults.json` under the home, behind
  session, CSRF and origin checks. The arm form pre-fills from them and shows
  which default applied. Defaults never arm anything and never change the
  pack's risk cap.
  - Scope: `src/krellbot/application/arm_defaults.py` (new), `src/krellbot/api/app.py`, `frontend/src/features/paper/StatusPanel.tsx`, `frontend/src/features/paper/client.ts`

- [ ] **M31.4 Strategy bundle round trip.** `application/strategy_bundle.py`
  exports one owned strategy as `{bundle_schema: '1', revisions: [canonical
  bytes, parent ids, created_at], receipts: [stored research results whose
  receipt.pack_sha256 matches a revision]}`, plus M29.1 run records when
  present. Import validates each revision with `pack.lint.check`, lists
  unsupported or unknown fields and returns a dry-run diff; commit creates new
  drafts only, never arms, never writes config or journal. Receipt windows

  - Scope: `src/krellbot/application/strategy_bundle.py` (new), `src/krellbot/api/app.py`, `frontend/src/features/strategies/SavedStrategyLibrary.tsx`

- [ ] **M31.5 Account-wide asset exclusions in the user policy.** Add an

- [ ] **M31.6 Apply a new revision to a paper arm in one confirmed step.**
  After the M31.2 diff is confirmed, one paper command disarms and re-arms

  - Scope: `src/krellbot/application/paper.py`, `src/krellbot/api/app.py`, `src/krellbot/run/__init__.py` (arm path, if touched), `frontend/src/features/strategies/RevisionCompare.tsx`

  - Accept: `KRELLBOT_HOME=$(mktemp -d) uv run --no-sync pytest -q tests/test_paper_apply_revision_keeps_position.py`
