# M29: reproducible research and verifiable strategy evidence

**Status:** proposed. Agents start M29 only after the owner merges this file
and after M28's agent tasks have merged, unless the owner reorders. (Proposed
as M28 in #625; renumbered so the V1 milestone, M28, goes first.)

**Exit / gate:** every research run, batch member, sweep trial and
walk-forward fold in the workstation can be reproduced from a run id that
names the pack identity, dataset manifest, engine version, costs and window.
Every batch and sweep reports all of its members and trials, including
failures. A locked holdout is scored only by a recorded confirmation run. A
pack can carry an evidence record that the engine verifies against the pack
bytes and that keeps historical, forward-paper and live results apart.
Commercial entitlement lapse never blocks exits, export or diagnostics.

Everything in M29 is local and free. No hosted service, new egress, pricing
or tier ships here. Background, the capability matrix and later tranches are
in [platform-initiative.md](../platform-initiative.md).

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks.
Agents keep `PAPER_ONLY_RELEASE` True. Never present backtest, sweep or
fixture results as market performance.

**Moved to M28:** #625's M28.10 (headless alerts, F17) is now M28.19, which
delivers alerts from the scheduled tick after M28.1 dedupes them per
occurrence. M28 also owns the research costs task (M28.9, F01: fee totals,
fee impact, slippage input, stressed rerun) and the Research display task
(M28.10, F19 and F20's display cells). M29 does not repeat them; tasks below
say where they reuse them.

**Pinned shapes (every task):** the 13-key receipt and its `metrics` keys
(`tests/test_backtest_engine.py:193-226`), `ResearchResult.detail`
(`DETAIL_KEYS` in `tests/test_backtest_entry_candle_stop.py`), the stored job
result `{legacy_receipt, trace}` (`tests/test_ns09_research_api.py:167`,
`tests/test_research_allow_gaps_boolean.py:142`), the JobV1 key set
(`tests/test_ns06_jobs.py:610-623`) and `BarRecord`
(`tests/test_eval_series.py:296-303`) stay as they are. New outputs go in a
new key of `research-jobs/<id>.json`, in a side-car outside `research-jobs/`,
or behind a new route. Never write another `*.json` file under
`research-jobs/`: `JobManager._restore_jobs` reads `payload["job"]` from every
such file.
